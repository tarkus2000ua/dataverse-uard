# Режим запуску UaRD: видимість API

Код UaRD для Dataverse 6.12 використовує параметр `:UardHidePublicApiUi`.
Значення `true` (також типове за відсутності параметра) залишає роботу з
токеном в інтерфейсі суперкористувачам. Значення `false` відновлює звичайну
видимість Dataverse. Для зміни параметра потрібен доступ до локального
адміністративного API. Політики доступу до API, ключі та записи в базі не
змінюються.

## Перший етап

1. Зберіть WAR із гілки з цією зміною. Публікуйте згенеровані HTML-файли
   довідки, а не шаблони з `customization/guide/`. У цій гілці вже збережено
   версію довідки для запуску. Перевірка збірки:

   ```bash
   python3 scripts/customization/build-guide.py --check
   ```

2. На сервері, де розгорнуто оновлення, встановіть режим запуску явно.
   Використовуйте чинний спосіб авторизації адміністративних запитів.

   ```bash
   SETTINGS_URL=http://localhost:8080/api/admin/settings
   curl --fail-with-body -X PUT --data-binary true "$SETTINGS_URL/:UardHidePublicApiUi"
   curl --fail-with-body "$SETTINGS_URL/:UardHidePublicApiUi"
   ```

3. Перевірте інтерфейс у нових вкладках або сесіях. У режимі запуску посилання
   в шапці веде на локальну довідку `/guide/`. Форми реєстрації приховують
   лише пункт із посиланням на `/misc/tou3_uk.html` або `/misc/tou3_en.html`;
   оригінальні значення `:ApplicationTermsOfUse` лишаються в базі.
   Якщо текст на сервері використовує інші адреси або формулювання щодо API,
   перевірте його окремо. Повні HTML-сторінки умов зберігаються на сервері,
   але в режимі запуску за цими адресами застосунок повертає 404.

## Відновлення на наступному етапі

1. Підготуйте повну довідку з того самого дерева вихідних файлів. Збирайте її
   в окремий каталог, щоб у робочій копії залишилася версія для запуску.

   ```bash
   FULL_GUIDE_DIR="$(mktemp -d)"
   python3 scripts/customization/build-guide.py --with-api --output "$FULL_GUIDE_DIR"
   python3 scripts/customization/build-guide.py --with-api --output "$FULL_GUIDE_DIR" --check
   ```

2. Перевірте, що в активному застосунку є повні сторінки умов API
   `misc/tou3_{uk,en}.html` та що обидва варіанти `:ApplicationTermsOfUse`
   містять потрібні посилання. Якщо цих файлів або налаштувань немає на
   цільовому сервері, використайте повні матеріали реєстрації, збережені
   оператором під час попереднього розгортання. Параметр видимості сам не
   створює сторінки чи локалізовані налаштування.
3. Перевірте, що `:NavbarGuidesUrl` вказує на потрібну довідку. Для
   локальної довідки збережіть кінцеву косу риску в URL `/guide/`.
   Встановіть `false` і опублікуйте підготовлений каталог довідки за
   чинною процедурою розгортання. Включіть повну згенеровану довідку в
   наступні артефакти, інакше новий WAR поверне варіант для запуску.

   ```bash
   SETTINGS_URL=http://localhost:8080/api/admin/settings
   curl --fail-with-body -X PUT --data-binary false "$SETTINGS_URL/:UardHidePublicApiUi"
   curl --fail-with-body "$SETTINGS_URL/:UardHidePublicApiUi"
   ```

4. Перевірте, що відновилися вкладка та її прямий URL, підказки про API,
   розділи довідки і посилання в умовах. Для повторного обмеження
   опублікуйте довідку, зібрану без `--with-api`, і встановіть `true`.

## Контроль після зміни режиму

| Сценарій | Режим запуску | Відкритий режим |
|---|---|---|
| Гість | Немає інструкцій про API в довідці, статті про репозитарій і формах реєстрації | Відображаються повні тексти |
| Звичайний користувач і адміністратор колекції | Немає пункту та вкладки токена. `/dataverseuser.xhtml?selectTab=apiTokenTab` відкриває інформацію акаунта | Вкладка токена й прямий URL доступні |
| Суперкористувач | Доступні перегляд, копіювання, створення, перевипуск і відкликання власного токена, а також адміністративні підказки | Та сама поведінка |
| Сторінка файлу й набір даних | Для звичайних користувачів відсутні прямі URL в метаданих і посилання на Data Access API в попередженні про розмір ZIP. Звичайне скачування, включно з кнопкою для файлу-пакета, працює | Видно URL і повні підказки |
| Сповіщення | Подія створення токена відсутня в списку, налаштуваннях і лічильнику звичайного користувача | Попередні записи та персональні налаштування знову видно |

Окремо перевірте файловий пакет із гостьовою книгою, якщо цей тип файлів
використовується, а також меню зовнішнього інструмента налаштування файлів.
Режим обмежує саме інтерфейс. HTTP API, `/openapi`, експорт даних і
наявні інтеграції залишаються доступними за чинними правилами.

## Перенесення з uard2 на основний UaRD

1. Зафіксуйте коміт і результат перевірки uard2. На основному сервері
   окремо визначте активний застосунок, контекст, назви мовних файлів і
   версію Dataverse. Перевірте, що там уже працюють потрібні сторінки,
   маршрути довідки й локалізовані умови.
2. Збережіть поточний артефакт застосунку, активні зовнішні мовні файли
   та попереднє значення параметра видимості. Повторіть перевірку
   сумісності з фактичними файлами основного сервера.
3. Якщо сервери використовують однакову базову збірку, використайте
   перевірений артефакт для цієї бази. Якщо збірки відрізняються,
   застосуйте коміт до джерел активної збірки основного сервера,
   зберігши його правки, і зберіть окремий WAR. Зміна містить Java,
   тому копіювання лише XHTML, HTML і перекладів недостатньо.
4. Оновіть застосунок штатним способом і додайте до чинних зовнішніх
   перекладів лише ключ `file.zip.download.exceeds.limit.detail.individual`
   із відповідних файлів `customization/lang/`. Для українського
   використайте наявний на сервері файл `Bundle_uk.properties` або
   `Bundle_ua.properties`. Застосуйте кроки режиму запуску вище та
   перевірте обидві мови, ролі, публічні сторінки і скачування.
5. Для технічного відкату розгорніть збережений попередній артефакт,
   відновіть мовні файли й попереднє значення параметра. Відкриття API
   на наступному етапі описане окремо вище і виконується без відкату
   застосунку.
